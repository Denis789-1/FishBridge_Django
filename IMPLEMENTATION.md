# Изменения FishBridge

## Что добавлено

- На странице водоёма можно выбрать дату и увидеть статус каждого сектора. Свободные секторы располагаются выше занятых.
- В форме бронирования добавлен выбор водоёма. Список секторов фильтруется по выбранному водоёму.
- В личном кабинете можно добавить оборудование к своему активному бронированию. Проверяется доступное количество на пересекающийся период, стоимость рассчитывается по цене за день, длительности тарифа и количеству.
- Егерь с ролью `ranger` может регистрировать улов по бронированию и закрывать визит после внесения всех видов рыбы.
- Для каждого вида рыбы задаётся цена за килограмм сверх нормы. При закрытии визита сервер суммирует обычный улов, сравнивает его с нормой тарифа и распределяет превышение между видами пропорционально их весу. Доплата рассчитывается по цене каждого вида.
- Для трофейного экземпляра тяжелее 5 кг егерь указывает вес и выбирает отпуск обратно в водоём или оплату по двойной цене за килограмм. Отпущенный трофей исключается из расчётного веса; оплаченный по двойному тарифу рассчитывается отдельно и не смешивается с обычным превышением нормы. Если трофейных экземпляров несколько, для каждого создаётся отдельная запись.
- Если в улове несколько видов рыб, общий вес обычного улова сверх нормы распределяется между видами пропорционально их весу; к каждой доле применяется цена соответствующего вида. Это выбранное правило распределения, поскольку в варианте задания точный способ распределения смешанного улова не задан.
- Результат расчёта сохраняется в доплате вместе с детализацией по видам рыб; рыболов видит итог в личном кабинете.
- Ихтиолог с ролью `ichthyologist` может просматривать виды рыб и партии зарыбления.
- Пользователь с ролью `admin` может открыть сводную панель с количеством записей и начислениями за период.
- Для сектора добавлены поля временного закрытия, причины и даты окончания. Эти поля доступны в административной панели Django.
- Журналы приложения ротируются ежедневно; сохраняются 30 предыдущих файлов.
- Добавлена команда резервного копирования SQLite: `python manage.py backup_database`.
- Добавлены автоматические тесты основных новых сценариев.

## Правило расчёта доплаты

- Норма вылова берётся из поля «Норма вылова, кг» выбранного тарифа.
- Егерь добавляет отдельные записи улова по каждому виду рыбы. В каждой записи указывается общий вес этой записи.
- Обычный улов — общий вес записи за вычетом веса указанного трофейного экземпляра.
- Превышение — положительная разница между суммой обычного улова и нормой тарифа.
- Если в улове несколько видов рыб, превышение распределяется между ними пропорционально весу обычного улова каждого вида. К полученной доле применяется цена за килограмм именно этого вида.
- Трофейный экземпляр тяжелее 5 кг исключается из обычного расчёта нормы. Если егерь выбирает отпуск, его вес сохраняется как отпущенный и не тарифицируется. Если выбирает двойной тариф, весь вес трофея отдельно умножается на цену соответствующего вида и на 2.
- Итоговая доплата и детализация по каждому виду сохраняются в записи доплаты. После расчёта бронирование получает статус «Завершено».

Так как в варианте задания не задано распределение превышения между несколькими видами рыб, в проекте используется пропорциональное распределение. Если преподаватель требует другое правило, его можно заменить в `main/services.py`.

### Настройка перед использованием

1. В административной панели откройте «Виды рыб» и укажите для каждого вида цену за килограмм сверх нормы.
2. В разделе «Тарифы» укажите норму вылова, например 5 кг.
3. Егерь открывает страницу «Учёт улова» и добавляет записи по всем видам рыбы.
4. Для экземпляра тяжелее 5 кг укажите его вес и выберите отпуск или двойной тариф. Для нескольких трофейных рыб создаются отдельные записи.
5. После внесения всего улова выберите бронирование в блоке «Закрыть визит» и нажмите кнопку расчёта.
6. Итог и расшифровка доступны егерю на странице учёта улова и рыболову в личном кабинете.

## После получения обновлённого проекта

В корневой папке проекта выполните:

```powershell
python manage.py migrate
python manage.py check
python manage.py test
```

Если проект запускается из уже обновлённого архива, миграция временного закрытия сектора уже применена к включённой базе данных. Команду `migrate` всё равно можно выполнить повторно: Django сообщит, что миграции уже применены.

## Роли и административная панель

Пользователи сайта хранятся в модели FishBridge. Для доступа к новым страницам задайте пользователю одну из ролей:

- `angler` — рыболов;
- `ranger` — егерь;
- `ichthyologist` — ихтиолог;
- `admin` — администратор.

Для управления водоёмами, секторами, тарифами, прокатом, видами рыб, партиями зарыбления, бронированиями и доплатами используется `/admin/`. Для входа туда нужна отдельная учётная запись Django Superuser, созданная командой `python manage.py createsuperuser`. Роль `admin` в пользовательской модели сайта сама по себе не авторизует в стандартной панели Django.

## Ограничения, которые ещё остаются

- Интерактивная карта водоёмов и QR-путёвка с проверкой QR-кода не реализованы.
- Историческая стоимость тарифа не сохраняется отдельным полем в бронировании. Поэтому отчёт по начислениям использует текущую цену связанного тарифа и явно помечен как расчёт по текущим ценам.
- Период проката наследуется от периода бронирования; отдельные даты выдачи и возврата в модели не хранятся.
- Email-уведомления не отправляются: сейчас используется консольный backend, а почтовые настройки не заданы.
- Стандартная панель Django использует отдельную учётную запись Superuser, а не пользовательскую роль FishBridge.

## Настройки окружения

Для локальной разработки проект использует тестовый ключ по умолчанию. Перед развёртыванием задайте собственный `DJANGO_SECRET_KEY` и отключите режим отладки через `DJANGO_DEBUG=False`.
